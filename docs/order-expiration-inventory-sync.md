# 订单过期与 Redis 库存同步：本阶段实施说明

日期：2026-10-04。

## 范围决策

用户决定本阶段只完成讨论中的第 3 项与第 5 项：未付款订单到期关闭，以及补货同步和 Redis 库存重建。其余边界 case 在本项目当前阶段不考虑，不作为本次交付前提。

暂不引入独立数据库预占表 / reserved_stock、完整 Saga、Outbox、请求级 Idempotency-Key、取消墓碑、epoch / fencing、Redis Cluster 跨分片协议、真实支付及退款。Redis 运行期故障时继续建单的原有降级策略保留，因此可能接受超过库存的未付款订单；最终付款仍由数据库条件扣减兜底。管理员将库存调低到未付款订单占用量以下时，本阶段只把 Redis 可售量限制为 0，不实现占用冲突处理。

[完整 Saga 设计](redis-inventory-saga-design.md) 保留为未来参考，不代表本次实现。本阶段使用定时数据库扫描和绝对快照同步，没有增减库存事件或版本化消息。

## 订单过期

- 保留订单和明细，不直接删除；API 返回 UNPAID / PAID / EXPIRED 状态。
- 新订单的 expiresAt 是数据库建单时间加 15 分钟；expiredAt 保存实际关闭时间，状态由付款时间和关闭时间推导。
- 历史截止时间按 createdAt + 15 分钟回填，不额外延长窗口；已付款订单仍是 PAID。
- 付款在库存锁和订单行锁下用数据库时钟检查截止时间。即使后台尚未关闭，也会关闭过期订单并返回 HTTP 409，要求重新下单；重复付款仍只扣一次库存。
- 后台启动即扫描，此后每 5 秒扫描一次；没有结算流量或没有配置 Redis 时仍关闭到期订单。
- 先提交数据库关闭，再同步 Redis。同步失败由后台下一轮重试，不回滚已提交的订单、付款或商品变更。
- 详情、用户历史和管理员列表显示 Expired；已打开页面更新截止状态并禁用付款按钮，后端检查是最终依据。

## 补货与重建

Redis 可售量 = Product.stock − 所有尚未付款、尚未关闭订单的商品数量之和；负数限制为 0。

到期但数据库尚未关闭的订单仍占用库存，必须先关闭才能释放。付款同时减少实物库存并解除占用，因此不会额外恢复已经卖出的库存。

一次 Lua 同步商品可售量、预占 Hash 和到期索引。库存键或预占数据丢失后，从数据库订单明细恢复，不能只按物理库存 SETNX 初始化。

触发点：建单预占前及建单结束后、付款及过期关闭后、管理员创建/修改/删除商品后、购物车发现库存键缺失时，以及启动和每 5 秒后台维护。补货沿用现有管理员设置库存绝对值接口。

建单、付款、过期、商品写入与重建共用 PostgreSQL 事务级 advisory lock，先库存锁再业务行锁。该锁支持多个应用实例；重建时不会覆盖本服务的在途 Redis 预占。每次在锁内读取最新数据库事实，没有旧消息覆盖新库存问题。

全量扫描、单把库存锁及锁内 Redis 调用是本项目当前规模下的简化选择，会串行化库存写入。本阶段不承诺秒杀吞吐、跨存储原子提交或完整故障恢复；Redis 同步失败时只承诺后台重试，不承诺瞬时一致。

## 数据库升级

生产配置 database.auto_migrate: false 时，先停止应用写入，在已完成原 commerce 迁移的数据库执行：

`backend/internal/infra/database/migrations/0004_order_expiration.up.sql`

脚本增加 expiresAt / expiredAt、截止时间索引，回填历史截止时间，并关闭已到期的未付款订单；可以重复执行。启用 AutoMigrate 的开发环境会增加字段并回填截止时间，后台随后关闭到期订单。

本次提供迁移文件，不自动修改配置中的业务数据库。

## 验证

用隔离的本地 PostgreSQL schema 与 Redis 验证：过期付款拒绝并保留明细、重复过期处理、到期索引丢失仍可关闭、补货扣除未付款占用、库存和预占数据丢失后的重建、付款与后台维护并发，以及没有结算流量的后台关闭。继续运行原有并发付款、购物车结算及多商品回滚测试。
