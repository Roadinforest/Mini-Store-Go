# 库存与订单并发约定

## 数据来源

- `Product.stock` 表示尚未付款扣减的实物库存。
- 未付款且 `createdAt` 距 PostgreSQL 当前时间不足 15 分钟的订单，其 `OrderItem.qty` 构成有效预占。
- 可售量 = 实物库存 − 有效预占量。购物车不预占库存。
- 预占到期后查询自动排除该订单，无须 Redis TTL、下一笔下单或后台清理任务；历史订单仍保留。
- 已过期订单仍可付款，但必须重新检查可售量，不能占用其他订单的有效预占。

## 并发与失败

下单在同一事务内锁定购物车，按商品 ID 排序锁定商品，检查可售量，创建订单并清空购物车。第二次提交同一已消费购物车返回“cart is empty”，不会生成第二笔订单。这是防重复消费，不是保存并重放 HTTP 幂等响应。

付款在事务内锁定并重读订单；已付款直接返回。锁定商品后，扣减实物库存并更新付款状态。检查时排除当前订单自己的预占。任一步失败，库存和付款状态一起回滚。

后台设置库存也锁定商品，且不允许把实物库存调低到有效预占量以下（HTTP 409）。补货立即反映到可售量，无须刷新缓存。数据库不可用时返回错误，不会跳过库存校验。

所有库存写操作必须遵循同一套商品锁约定。当前实现针对 PostgreSQL 默认 READ COMMITTED 隔离级别；更改隔离级别时需另外处理事务重试。

## 升级

库存路径已移除 Redis 双写；Redis 连接配置保留供其他用途。旧的 `stock:product:*`、`reservation:order:*` 键不再读取，无须删除这些键才能启动。

已有订单直接参与预占计算，无须迁移订单数据。过去 15 分钟内的未付款订单都会计入预占，包括旧版本在 Redis 故障时跳过预占的订单；若历史数据已经超额预占，会暂时阻止新增下单，直到付款或预占到期。

已有数据库先执行 `docs/sql/inventory-indexes.sql` 中的两条索引语句（分别执行，不放入事务）；开发环境 AutoMigrate 会创建同名索引。索引用于避免预占查询扫描全表。

切换时先停止旧版本处理下单/付款并等待在途事务结束，再启动新版本。不要让使用 Redis 预占的旧实例与使用数据库预占的新实例混合处理交易。回滚同样需要停写切换，并重新处理旧 Redis 库存状态，不能直接恢复使用遗留缓存。

## 验证

提供一套独立 PostgreSQL 测试库，通过以下命令运行集成测试及 race 检查：

```sh
cd backend
TEST_DATABASE_DSN='postgres://USER:PASSWORD@HOST:PORT/TEST_DB?sslmode=disable' make test-integration
```

每个测试创建独立 schema 并在结束后删除；不会读取项目业务配置中的数据库。未设置 `TEST_DATABASE_DSN` 时，普通 `go test ./...` 会跳过数据库集成测试，`make test-integration` 则明确报错。

覆盖重复付款、重复下单、并发争抢库存、事务失败回滚、补货保留预占、库存下调冲突、预占到期自动释放和过期订单付款。
